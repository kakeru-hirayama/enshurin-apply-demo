# 東京大学演習林　利用申込システム（試作）

東京大学大学院農学生命科学研究科附属演習林の、利用申込のしくみを作り直す試みです。

**https://kakeru-hirayama.github.io/enshurin-apply-demo/**

---

## このリポジトリのデータについて

**ここに置かれているデータは、すべて架空のものです。**
実在の利用者や研究課題を示すものではありません。

件数・利用日数・人数・施設の分布のみ、実際の運用規模にもとづいています。
氏名・メールアドレス・所属・研究課題名・連絡先は、すべて置き換えてあります。

外部との通信は行いません。入力された内容がどこかへ送られることはありません。

## 背景

現在の運用には、次の課題があります。

```
・申込の処理はほぼすべて紙で行われている
　人数の変更などは、印刷した申込書に赤ペンで書き込む
　書き換えの際に誤りが生じることがある

・許可を出した後の所内のやり取りが、システムの外にある
　担当の割り当て、宿泊の調整、林道の安全確認
　利用が終わって報告書を書くとき、誰が対応したかを探し直す

・本部での集計に手作業が多い
　139列のデータに集計用の列を80以上追加し、
　宿泊施設ごとに同じ形の数式を23施設分並べている

・過去に2度、作った人がいなくなって動かなくなった経験がある
　本部のデータベース（MySQL＋PHP）
　旧FileMaker（20年間、必要な画面を整備しきれないまま）
```

## 設計の考え方

### 画面とデータを直接つながない

```
　　利用者の画面        職員の画面        将来のアプリ
　　　　　│                │                 │
　　　　└────────┴────────┘
　　　　　　　　　　　　│
　　　　　　　　　【 API層 】
　　　　　　　　　　　　│
　　　　　　　　　【 アダプタ 】
　　　　　　　　　　　　│
　　　　　　　┌──────┴──────┐
　　　　スプレッドシート　　　Google ドライブ
```

**アダプタを差し替えると、保存先が変わります。** 画面は1行も変わりません。

引き継いだ方が知る必要があるのは、API層の関数の名前と、その入出力の形だけです。
データがどこにどう保存されているかを知る必要はありません。

### 演習林ごとの違いを、画面に書かない

7つの演習林で、手続きが大きく違います。

```
様式の分かれ方   北海道は8つのファイル、秩父は4書類が1ファイル
締切の決め方     前月20日／前月15日／20日前／10日前／5日前／2週間前
年度計画の承認   ある施設とない施設がある
許可証の発行     4施設は発行、3施設は記載なし
利用後の報告     利用ごと／課題ごとに2年間／記載なし
```

これらはすべてデータ（マスタ）として持ち、画面には条件分岐を書きません。
施設が増えても、画面のコードは変わりません。

## ファイル構成

```
api/
  schema.js          データの定義。表を足すときは必ずここを直す
  api.js             ★API層。画面から呼ばれる窓口
  adapter_memory.js  データ層（開発用・ブラウザのメモリ）
  adapter_sheets.js  データ層（本番用・Google スプレッドシート）
  deadline.js        締切の計算。施設ごとの分岐はここに集める
  export.js          Excel・Word・CSVの書き出し
  mail.js            メールの送信（Google Apps Script用）

web/
  user.html          利用者の画面
  staff.html         職員の画面

docs/
  api.md             API仕様。引き継ぎの本体
```
